# v2 Phase 6 — B·C·D 동결 및 미래 Shadow/KIS 모의검증 명세

## 상태와 목적

- Experiment ID: `EXP-20260826-013`
- 상태: 설계 동결, 최종 학습·모델 hash 동결 전
- 독립 평가 시작 가능일: 2026-08-27 이후
- 목적: 펀더멘털의 느린 분기 시계열과 기술 신호의 빠른 일별 시계열을 분리 학습한 뒤, 한 번 동결한 결합 모델을 새로 도착하는 데이터에서 순차 검증한다.

2004~2023은 이미 모델 개발에 사용된 기간이다. 이 기간의 결과는 학습·내부 walk-forward 진단에는 쓸 수 있지만 새 Test/OOS 증거로 부르지 않는다. 기존 v1의 2024~2025 봉인 자료는 접근하지 않는다.

## Agent B — 느린 펀더멘털 후보 생성

- 입력: 확정 재무제표 수치만 사용한다. 차트·최근 수익률·뉴스·공시 텍스트는 사용하지 않는다.
- 시점: 접수일 다음 KRX 세션부터 해당 재무상태를 사용할 수 있다.
- 변수: 수익성·밸류에이션·재무건전성·성장성 20개와 252세션 희석도 1개다.
- 전처리: 동일 시점 PIT KOSPI 200 안에서 percentile·robust z-score를 Train 내부에서 적합한다.
- 모델: `XGBRanker(objective="rank:ndcg")`다. 동일 날짜를 query group으로 둔다.
- 출력: 시가총액 상위 200 안에서 일별 펀더멘털 Top 30과 순위·점수다.
- 재무 공시가 없던 날에는 최신 확정 상태를 유지하며, 정정 공시는 새 접수일 다음 세션부터 교체한다.

## Agent C — 빠른 기술 실행 점수

- 입력: t일까지 완성된 40거래일 OHLCV 6채널만 사용한다. 재무자료는 보지 않는다.
- LSTM 분기: 향후 10세션 실현변동성을 예측한다.
- 1D CNN 분기: t+1 시가 진입 후 10세션 이내 +10%가 -5%보다 먼저 도달할 확률을 예측한다. 같은 일봉에서 둘 다 닿으면 `STOP_FIRST`다.
- 최종 기술 점수는 CNN 성공확률과 LSTM 변동성 감점을 결합한다.
- 신호는 t일 종가 후 확정하고 주문 의도는 t+1 시가에만 생성한다.

## Agent D — 시간축 결합과 주문 정책

1. Agent B의 당일 Top 30만 느린 품질 후보군으로 허용한다.
2. 그 30개 안에서 Agent C의 성공확률과 변동성으로 당일 우선순위를 만든다.
3. B·CNN·역변동성 가중치는 과거 내부 nested anchored walk-forward에서만 grid search한다.
4. 선택된 단일 가중치, scaler, 모델 상태와 모든 hash를 미래 관측 전에 동결한다.
5. CNN 확률 0.55 이상은 목표비중 5%, 0.65 이상은 11%로 하되 최대 10종목만 허용한다.
6. 전일 종가 대비 시가 괴리 절댓값 5% 초과 시 진입하지 않는다.
7. -5% 손절, +10% 익절, 최대 10세션 보유, no pyramiding을 적용한다.

과거 D3처럼 서로 다른 점수척도에 0.05·0.075를 그대로 적용하지 않는다. 0.55·0.65는 CNN의 확률 척도이며, 미래 평가 중에는 변경하지 않는다.

## KIS 모의투자 역할

KIS 모의투자는 역사적 백테스트가 아니라 현재 시장에서 주문 전송·체결·잔고·재시작·중복주문 방지를 검증하는 미래 순차 실행 환경이다. 모델 A의 모의투자 결과를 보고 모델 B를 만든 경우, A가 경험한 기간은 B에게 다시 독립 OOS가 되지 않는다.

실행 순서는 다음과 같다.

1. 과거 개발자료에서 nested walk-forward로 B·C·D 학습 절차를 확정한다.
2. 최종 모델·가중치·임계값·비용·코드·설정·데이터 hash를 동결한다.
3. 최소 20거래일 shadow-only로 신호·주문 의도만 기록한다.
4. shadow 감사가 통과한 뒤 사용자 별도 승인으로만 KIS 모의계좌 주문을 허용한다.
5. 사전 정의한 평가기간 동안 모델을 수정하지 않는다.
6. 실패하면 새 Experiment로 수정하되 이미 본 forward 기간은 개발자료가 되며, 다음 평가에는 더 미래의 새 기간을 사용한다.

## 현재 구현 경계

- `configs/v2_phase6_forward_shadow.json`은 `shadow_only`이고 KIS 네트워크와 주문을 모두 false로 강제한다.
- 설정에 API key·secret·token·계좌번호를 저장하지 않는다.
- `src/kospi200_forward_release/`는 계약 검사와 t+1 주문 의도 생성만 제공한다.
- B의 XGBRanker 최종 학습, C 재학습, D grid 선택과 모델 hash 동결이 끝나기 전에는 주문 의도를 생성할 수 없다.
- KIS 실계좌·모의계좌 API 호출, 서버 배포, 실제 주문은 이번 단계 범위가 아니다.

## Codex Handoff

다음 구현은 B XGBRanker 학습기와 D nested walk-forward 선택기다. 과거 성과를 독립 Test로 주장하지 않고 최종 후보를 만들기 위한 개발 적합으로만 실행한다. 모델 hash가 동결되면 `v2_phase6_forward_shadow.json`의 `TRAINING_PENDING`을 실제 hash와 단일 가중치로 교체하고, 그 이후 도착하는 데이터만 shadow 평가한다.
