# KOSPI 200 펀더멘탈·테크니컬 멀티에이전트 v2 구조

## 1. 전환 목적

기존 v1은 KOSPI 100의 가격·거래량만으로 매일 종목 점수를 만드는 연구였다. 여러 구조가 비용 차감 지수 초과수익을 안정적으로 만들지 못했고, 2004~2023의 개발 결과는 이미 관찰됐다. v2는 기존 결과를 지우거나 성공으로 재해석하지 않고 다음 두 축을 추가한다.

1. Universe를 동시점 실제 KOSPI 200으로 확대한다.
2. 확정된 분기 재무제표만 사용하는 펀더멘탈 에이전트를 기술 에이전트와 분리한다.

장기 목표는 높은 단기 수익률이 아니라 비용 차감 장기 복리, 낮은 낙폭, 연도·regime 안정성이다.

## 2. 데이터·에이전트 구조

### Agent A — Data/Audit

- KRX KOSPI 200 날짜별 실제 구성종목
- 기존 보유 KOSPI 전체 OHLCV·거래대금·시가총액·상장주식 수를 재사용하고, KOSPI 200 지수는 benchmark가 없을 때만 별도 수집
- OpenDART 접수번호·접수일·분기/반기/사업보고서 전체 재무제표
- 종목코드·법인코드·security ID의 시점별 연결
- Corporate Action, 거래정지, 편입·편출, 정정공시 처리

### Agent B — Fundamental Ranker

차트와 향후 가이던스는 사용하지 않는다. 각 재무제표는 DART 접수일 다음 KRX 거래일부터만 사용할 수 있다. 연결재무제표를 우선하고 없을 때만 별도재무제표를 사용한다.

고정 후보군은 수익성 5개, 가치 5개, 건전성 5개, 성장성 5개다. 원값과 유니버스/섹터 단면 percentile·robust z-score를 만들되, 결측치를 미래값이나 다른 분기로 채우지 않는다. 섹터 표본이 5개 미만이면 같은 날짜의 전체 KOSPI 200 단면으로 fallback한다.

XGBRanker `rank:ndcg`는 후보 모델이지 확정 모델이 아니다. 선형/규칙 baseline과 동일한 fold·비용에서 비교하며, 모델·하이퍼파라미터는 결과 확인 전에 새 Experiment ID로 등록한다.

### Agent C — Technical/Execution Ranker

OHLCV·거래대금·지수·breadth만 사용한다. 매일 모든 KOSPI 200 구성종목에 동일한 계산 체계를 적용하고, `t`일 장 종료 뒤 점수를 확정해 `t+1` 이후에만 주문한다. CNN/LSTM·분봉은 별도 데이터와 baseline을 확보한 뒤에만 후보가 된다.

### Agent D — Meta Allocator

Agent B의 분기 점수를 일별로 forward-available 상태로 유지하고 Agent C의 일별 점수와 결합한다. B와 C를 한 모델에 즉시 섞지 않고 다음 순서로 비교한다.

1. B 단독 장기 ranker
2. C 단독 일별 ranker
3. B의 상위 후보 안에서 C로 진입 순위 결정
4. B·C 점수의 Train-only stacking/meta model

결합 가중치, 매수 임계값, 보유 수, 손절·익절은 사전등록한다. 사람이 결과를 보고 임의로 비중을 바꾸지 않는다.

## 3. 20개 펀더멘탈 Factor 계약

| 영역 | Factor |
|---|---|
| 수익성 | ROE, ROA, 영업이익률, 순이익률, 영업현금흐름/자산 |
| 가치 | 이익수익률, 장부가/시가총액, 매출/시가총액, 영업현금흐름/시가총액, 잉여현금흐름/시가총액 |
| 건전성 | 부채/자본, 부채/자산, 유동비율, 현금/자산, 자본비율 |
| 성장성 | 매출, 영업이익, 순이익, 자산, 자본의 전년동기 성장률 |

정확한 ID는 `configs/fundamental_factor_contract_v1.json`을 따른다. 금융업처럼 계정구조가 다른 종목은 억지로 일반기업 공식을 채우지 않고 별도 sector contract가 승인될 때까지 결측으로 둔다.

## 4. Point-in-Time 원칙

- 결산일이나 분기말이 아니라 DART 실제 접수일을 정보 공개시점으로 사용한다.
- 장 종료 후 접수된 시각을 확인할 수 없으면 보수적으로 다음 거래일부터 사용한다.
- 정정공시의 수정값은 정정 접수일 전 날짜로 소급하지 않는다.
- 오늘 조회한 최신 재무제표를 과거 모든 날짜에 붙이지 않는다.
- 분기 값은 다음 유효 공시 전까지만 유지하며 stale age를 함께 기록한다.
- 시가총액 기반 Factor는 같은 신호일의 KRX 시가총액만 사용한다.
- PIT KOSPI 200 구성종목만 단면 변환과 rank에 참여한다.

## 5. 데이터 기간과 증거 상태

- 2004~2023: 기존 결과를 이미 본 개발·학습 전용 기간. 새 모델의 독립 OOS가 아니다.
- 2015~2023: OpenDART 표준 전체 재무제표로 구축 가능한 초기 펀더멘탈 개발기간.
- 2024~2025: 기존 v1 봉인 OOS. v2 개발에서 접근하지 않고 KOSPI 200용 새 OOS로 전용하지 않는다.
- 2026-08-26 이후: v2 명세·모델 동결 뒤 수집되는 forward paper/shadow 후보 기간.
- 최종 채택용 독립 OOS: 충분한 forward 기간이 쌓인 뒤 별도 승인한다.

과거 실패 실험은 삭제하지 않는다. registry와 요약 결과는 append-only로 보존하고, 해당 기간을 `consumed`로 표시해 새 OOS처럼 재사용하지 않는다. 대용량 실패 산출물은 요약·manifest·hash를 보존한 뒤 별도 승인으로 정리할 수 있다.

## 6. 현재 완료 범위와 비목표

현재 완료한 것은 v2 문서, KRX/OpenDART 수집기, PIT 정규화 계약, 20개 Factor 계산·단면 변환 코드와 테스트다. 실제 외부 데이터 수집, XGBRanker 학습, 백테스트, Development Test, 실주문은 수행하지 않았다.

## Codex Handoff

1. `tools/collect_krx_kospi200_v2.py`로 2004~2023 KRX KOSPI 200 구성종목만 수집한다.
2. `tools/collect_dart_kospi200_fundamentals_v2.py`로 2015~2023 재무제표를 수집한다.
3. `tools/normalize_dart_kospi200_fundamentals_v2.py`로 공개시점이 확인된 facts만 정규화한다.
4. 데이터 감사 완료 전 Agent B 모델이나 백테스트를 시작하지 않는다.
